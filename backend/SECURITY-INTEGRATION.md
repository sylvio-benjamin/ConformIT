# Security integration guide

This file is generated by WebSecKit. It explains how to wire each selected module.

## Profile

- Framework: `fastapi`
- Project type: `saas`
- Modules: `config`, `headers`, `cors`, `https`, `rateLimit`, `bruteForce`, `captcha`, `botProtection`, `authentication`, `mfa`, `authorization`, `validation`, `uploads`, `csrf`, `api`, `logging`, `payments`, `injection`

## Status legend (checklists)

- `[ ]` Not verified
- `[x]` Compliant
- `[!]` Needs a fix
- `[-]` Not applicable

## Bootstrap

1. Treat `security/` as a Python package (it includes `__init__.py` files).
2. FastAPI already depends on Starlette and Pydantic — no extra security libraries required for V1.
3. Wire middleware:

```python
from security.middleware import WebSecKitMiddleware
app.add_middleware(WebSecKitMiddleware, trust_proxy=True)
```

4. Run tests: `pytest security/tests`.

## Environment

Copy `security/.env.example` keys into your real `.env`. Never commit secrets.

## HTTP security headers (`headers`)

CSP, HSTS, nosniff, Referrer-Policy, Permissions-Policy, frame-ancestors.

| | |
|---|---|
| What it does | Réduire XSS, clickjacking, MIME sniffing et fuites de referrer. |
| Dependencies | Aucune bibliothèque. Next.js : middleware natif. Express : res.setHeader. |
| Configuration | CSP dans headers/csp ; HSTS max-age dans security.config. |
| Where to import | Next.js : racine middleware.ts. Express : app.use. Vite : plugin dans vite.config. FastAPI : middleware Starlette. |
| How to use | Appliquer sur toutes les réponses HTML et API, y compris les erreurs. |
| How to test | Playwright / curl : vérifier la présence de chaque header. |
| What to tune | CSP directives, HSTS includeSubDomains/preload, Permissions-Policy. |
| Limits | CSP cassera les scripts inline et les CDN non listés. Prévoir des nonces si besoin. |

## CORS (`cors`)

Allowlist d'origines, pas de wildcard avec credentials.

| | |
|---|---|
| What it does | Empêcher un navigateur tiers d'appeler l'API avec les cookies de l'utilisateur. |
| Dependencies | Aucune. N'ajoutez pas cors/* avec origin: '*'. |
| Configuration | CORS_ALLOWED_ORIGINS ou securityConfig.cors.allowedOrigins. |
| Where to import | Middleware global, avant les routes. |
| How to use | Refuser toute origine absente de la liste. Varier Access-Control-Allow-Origin. |
| How to test | OPTIONS depuis une origine inconnue doit échouer. |
| What to tune | origines, méthodes, headers, maxAge, credentials. |
| Limits | CORS ne remplace pas l'autorisation serveur. Un client non-navigateur ignore CORS. |

## HTTPS enforcement (`https`)

Redirection HTTPS et rejet des cookies non Secure en production.

| | |
|---|---|
| What it does | Éviter le downgrade HTTP et le vol de session en clair. |
| Dependencies | Terminaison TLS au reverse proxy (recommandé) ou nœud TLS. |
| Configuration | Trust proxy : X-Forwarded-Proto uniquement derrière un proxy de confiance. |
| Where to import | Premier middleware de la chaîne. |
| How to use | En production, rediriger 308 vers https://. Ne pas forcer en local. |
| How to test | Vérifier Strict-Transport-Security une fois HTTPS actif. |
| What to tune | enabledInDevelopment (false par défaut). |
| Limits | Sans proxy de confiance, X-Forwarded-Proto est spoofable. |

## Rate limiting (`rateLimit`)

Limites globale, par IP, par utilisateur et par endpoint.

| | |
|---|---|
| What it does | Freiner brute-force, scraping et déni de service applicatif simple. |
| Dependencies | Mémoire locale en V1. Redis recommandé dès plusieurs instances. |
| Configuration | Fenêtres et quotas dans security.config.rateLimit. |
| Where to import | Middleware global + décoration des routes sensibles (login, reset, webhooks). |
| How to use | rateLimit.check({ key, bucket }). Si denied → 429 + Retry-After. |
| How to test | tests unitaires du limiteur ; test d'intégration sur /login. |
| What to tune | windowMs, max, buckets named (global, ip, user, login, api). |
| Limits | Store mémoire non partagé entre replicas. Derrière un LB, clé IP = X-Forwarded-For de confiance. |

## Brute-force / login protection (`bruteForce`)

Seuil d'échecs, backoff, verrouillage temporaire, timing constant.

| | |
|---|---|
| What it does | Ralentir les attaques sur login et reset password. |
| Dependencies | Module rate-limit + password hashing (comparaison dummy). |
| Configuration | maxAttempts, lockoutMs, dummyHash dans security.config.auth. |
| Where to import | Dans le handler de login, avant et après la vérification du mot de passe. |
| How to use | recordFailure(key) / resetOnSuccess(key). Toujours hasher même si user absent. |
| How to test | N échecs → locked. Succès → compteur à zéro. |
| What to tune | seuil, durée de lockout, clé (ip+username). |
| Limits | Un attaquant distribué contourne un lockout par IP. Combiner captcha + MFA. |

## Cloudflare Turnstile (`captcha`)

Vérification serveur du token Turnstile pour formulaires publics.

| | |
|---|---|
| What it does | Freiner les soumissions automatisées de formulaires publics. |
| Dependencies | fetch natif. Secret : TURNSTILE_SECRET_KEY (jamais côté client). |
| Configuration | sitekey côté front, secret côté serveur via env. |
| Where to import | Handlers de contact, inscription, login si volumétrie abusive. |
| How to use | verifyTurnstileToken(token, ip). En échec → 400 générique. |
| How to test | Mock de siteverify ; token absent rejeté. |
| What to tune | timeout, hostname allowlist optionnelle. |
| Limits | Ne remplace pas le rate limiting. Le widget peut être contourné ; la vérif serveur est obligatoire. |

| | |

Secret TOTP, URI otpauth, vérification à fenêtre glissante.

| | |
|---|---|
| What it does | Second facteur pour comptes privilégiés (admin, paiements). |
| Dependencies | HMAC-SHA1 natif. QR code : lib front optionnelle, pas dans le toolkit. |
| Configuration | issuer, digits=6, period=30, window=1. |
| Where to import | Enrollment MFA + étape login après mot de passe. |
| How to use | generateTotpSecret, buildOtpauthUrl, verifyTotp. |
| How to test | Code valide dans la fenêtre ; code hors fenêtre rejeté. |
| What to tune | window, issuer. |
| Limits | Protéger le secret TOTP au repos (chiffrement). Prévoir codes de récupération hashés. |

| | |
|---|---|
| What it does | Empêcher l'élévation de privilèges et l'accès horizontal (IDOR/BOLA). |

## CSRF (double-submit) (`csrf`)

Jeton CSRF pour les mutations cookie-based. Non généré pour les API Bearer pures.

| | |
|---|---|
| What it does | Empêcher un site tiers de déclencher une action authentifiée par cookie. |
| Dependencies | Aucune. Pattern double-submit + SameSite. |
| Configuration | cookie name, header name, SameSite=Lax ou Strict. |
| Where to import | Middleware POST/PUT/PATCH/DELETE des routes cookie-auth. |
| How to use | issueCsrfToken(); verifyCsrf(cookie, header). |
| How to test | Mutation sans header → 403. GET non soumis au CSRF. |
| What to tune | exempt paths (webhooks HMAC, health). |
| Limits | Inutile et trompeur sur une API JWT Bearer sans cookies. SameSite n'est pas un CSRF complet à lui seul. |

## Payments / webhooks (`payments`)

Checkout hébergé, prix serveur, signature Stripe, idempotence, lock de créneau.

| | |
|---|---|
| What it does | Stripe Checkout (ou autre PSP hébergé) crée la session côté serveur. Le webhook signé confirme. Jamais un flag client. |
| Dependencies | STRIPE_SECRET_KEY + STRIPE_WEBHOOK_SECRET. Pas de SDK obligatoire dans le toolkit. |
| Configuration | Montant catalogue, success/cancel URLs, skew de signature, TTL du lock. |
| Where to import | POST checkout (authz + prix) et POST webhook (raw body uniquement). |
| How to use | resolveCheckoutAmount({ catalogAmountCents }); verifyStripeSignature(...); mark(event.id); applyPaymentWebhook(...). |
| How to test | security/tests/payments.test.ts — montant client, signature, replay, lock, mode test. |
| What to tune | deposit cents, lock TTL, signature tolerance. |
| Limits | Le store mémoire n'est pas partagé entre instances. Le redirect success n'est pas une preuve de paiement. |

## Injection guards (`injection`)

Helpers anti-injection et règles : requêtes paramétrées uniquement.

| | |
|---|---|
| What it does | Empêcher SQL/NoSQL/command/path/template injection par construction, pas par blacklist. |
| Dependencies | Aucune. Utilisez l'ORM / le driver paramétré du projet. |
| Configuration | Aucune. Les concaténations SQL sont interdites par politique. |
| Where to import | Accès data, filesystem, shells (à éviter), templates. |
| How to use | assertSafeRelativePath(); never build SQL with string concat. |
| How to test | Path traversal rejeté ; detectConcatenatedSql flagge un pattern. |
| What to tune | root directory allowlist. |
| Limits | Aucune blacklist n'est complète. Le seul modèle sûr est paramétrage + allowlist + moindre privilège. |

## What this toolkit does not do

- It does not prove the application is secure.
- It does not replace a human review, dependency audit, or pentest.
- Generated modules must be wired; unused files protect nothing.
