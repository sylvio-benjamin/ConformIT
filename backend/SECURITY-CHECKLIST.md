## web-application

# Web application

- [ ] Authentication, session and authorization modules are wired, not only generated
- [ ] Every privileged action is authorized on the server
- [ ] Resource IDs are checked for ownership (IDOR/BOLA)
- [ ] Cookies are `HttpOnly`, `Secure` (production), and `SameSite`
- [ ] Session idle and absolute timeouts are enforced
- [ ] Password policy and scrypt (or equivalent) hashing are used
- [ ] Login uses dummy hashing when the user does not exist
- [ ] Security headers including CSP apply to authenticated pages
- [ ] Rate limits cover login, reset and APIs
- [ ] Admin UI is not reachable without `admin:access`
- [ ] Logs capture auth failures and admin actions without secrets
- [ ] CSRF is enabled for cookie-session mutations, or explicitly `[-]` for Bearer-only

## authentication

# Authentication

- [ ] Passwords are hashed with scrypt/argon2/bcrypt — never reversible encryption
- [ ] Password policy rejects short and common passwords
- [ ] Login errors are generic (`Invalid credentials.`)
- [ ] Timing is similar for existing and missing accounts
- [ ] Reset tokens are random, stored hashed, single-use, short-lived
- [ ] Reset does not reveal whether the email exists
- [ ] Session IDs are 256-bit random values
- [ ] Logout invalidates the server-side session
- [ ] MFA is required for administrators when the module is in scope
- [ ] Brute-force lockout is active on login and reset

## admin-panel

# Admin panel

- [ ] Admin routes require an authenticated principal with `admin:access`
- [ ] UI hiding is not the control — the API enforces the same rules
- [ ] Admin actions are logged (`admin.action`)
- [ ] Permission changes are logged (`permission.change`)
- [ ] MFA is enabled for admin accounts
- [ ] Rate limits are stricter than the public site
- [ ] Session timeout is shorter than for regular users (tune if needed)
- [ ] Admin hosts/paths are not indexed (`X-Robots-Tag` / robots) where relevant
- [ ] Break-glass accounts are documented and monitored

## api

# API

- [ ] Every route authenticates unless explicitly public
- [ ] Authorization is re-checked per resource, not only at login
- [ ] Request bodies, query params and path params are schema-validated
- [ ] Unknown properties are rejected on mutations
- [ ] Pagination is capped (`maxPageSize`)
- [ ] Body size is capped
- [ ] Error payloads never include stack traces in production
- [ ] CORS uses an allowlist; never `*` with credentials
- [ ] Rate limits are per IP and per user/token
- [ ] Webhooks verify signatures and reject stale timestamps
- [ ] Sensitive endpoints are not listed in public OpenAPI without auth
- [ ] Tokens are sent in `Authorization` headers, not query strings

## ecommerce

# E-commerce / payments

- [ ] Payment webhooks verify HMAC (or PSP signature) on the **raw** body
- [ ] Fulfillment is idempotent (replay of a valid webhook is safe)
- [ ] No business logic runs before signature verification
- [ ] Card data never touches your logs, analytics, or error tracker
- [ ] PCI scope is minimized (hosted fields / PSP checkout)
- [ ] Order access is owner-scoped (no IDOR on `/orders/:id`)
- [ ] Refunds and price changes are admin-only
- [ ] CSRF or origin checks protect checkout if cookies are used
- [ ] Rate limits on checkout, webhooks and account endpoints
- [ ] Inventory and coupon checks happen server-side

## production

# Production

- [ ] `NODE_ENV` / `ENV` is `production`
- [ ] HTTPS is enforced; HSTS is enabled
- [ ] Debug endpoints and source maps are disabled
- [ ] Secrets live in the environment or a vault, not in git
- [ ] `.env` is gitignored; `.env.example` is present
- [ ] Dependency audit ran (`npm audit` / `pip-audit`) and highs are triaged
- [ ] Backups of data stores are encrypted and access-controlled
- [ ] Security logs are retained and access-restricted
- [ ] Reverse proxy strips incoming `X-Forwarded-*` from the public internet, then sets its own
- [ ] Uploaded files (if any) are not executable and not served from the app origin if possible
- [ ] Incident contact and rollback path are documented
- [ ] This checklist was completed by a human, not only by WebSecKit

Completing this checklist does not prove the application is secure. It is a process aid, not a certification.
